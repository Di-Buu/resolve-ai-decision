# ResolveBench 冒烟评测

这组 10 个案例评测 V0.7 的“问题描述 → 结构化决策对象”切片，不代表完整产品质量，也不代替真实用户验证。`resolvebench_flow.json` 另提供从问题整理到最终留档的纵向流程评测。

## 运行

1. 在项目根目录 `.env` 中配置有效的阿里云百炼 `DASHSCOPE_API_KEY`。
2. 运行 `npm start`。
3. 在另一个终端运行 `npm run eval:smoke`。

可用 `npm run eval:smoke -- --limit=3` 先运行前三例。结果写入 `evals/results/`，包括模型、响应 ID、耗时、token 用量、逐项检查和模型原始结构化输出；结果文件默认不提交，以避免把一次偶然运行当成固定基准。若在 `.env` 填写当前输入和输出单价，报告会同时估算本次成本。

如需快速查看公开案例结构并验证脚本，可运行两例 Sample：

```powershell
npm run eval:smoke -- --dataset=resolvebench_sample.json
```

评测报告会记录数据集文件名，避免把 Sample、Smoke 与其他测试结果混在一起。

真正的 Holdout 集不进入公开仓库，避免后续开发直接针对保留案例优化。公开报告只保留题量、类别分布、文件哈希和汇总成绩。它仍由项目内部设计，不能表述为真实用户验证或外部盲测结论。

## 当前检查项

- 是否覆盖最低参与方数量。
- 是否识别足够的冲突和信息缺口。
- 是否区分预期的硬约束、软偏好与假设。
- 是否覆盖场景关键语义，而不是要求固定文案。
- 是否保留人工最终决定边界。

这些是首轮规则型冒烟门槛。后续需要增加人工标注、错误严重度和纵向流程重复运行；当前已经完成一次性建议与 Resolve 结构化入口的早期切片对照，更完整的同输入工作流对照仍待补充。

## 纵向流程评测

```powershell
npm run eval:flow -- --limit=1
```

也可以只运行指定案例：

```powershell
npm run eval:flow -- --cases=RF-002,RF-003
```

脚本在临时 SQLite 数据库中创建决策，调用真实模型完成每位参与者的观点结构化、共同问题汇总、需求判断、澄清、方案和检查，再由确定性事件模拟本人确认、负责人确认、方案审阅和最终留档；如果检查发现证据不足，会继续走补充证据和重新生成路径。方案检查还要求每个候选方案提供至少两个行动步骤、回退办法和成功信号。数据库在运行结束后清理，结果 JSON 写入 `evals/results/` 并默认忽略，不把一次运行结果伪装成固定基准。

新增观点与共同问题调用后，2026-09-15 已用当前默认 Plus 完整运行 3 个案例：RF-001、RF-002、RF-003 均通过全部规则检查，平均耗时约 123 秒，三例通过运行合计估算模型成本约 ¥0.4041。改造前 Flow 基线为平均约 47 秒、三例合计约 ¥0.1223；两者不可直接视为同一版本结果。新版结果仍是内部工程信号，不据此判断真实用户效果或方案是否更有启发。

## 一次性建议基线

```powershell
npm run eval:baseline -- --limit=5
npm run eval:baseline -- --cases=RB-010
```

基线使用同一模型和输入，对比“一条回复直接给建议”与 Resolve 结构化入口。当前只检查参与者、冲突、信息缺口、约束类型、关键语义、下一步和人工边界；它不是完整工作流因果实验，也不证明真实用户效果。
